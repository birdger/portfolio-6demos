# 项目5 PRD:多租户 SaaS 平台(图书馆云服务)

## 定位
把项目1的图书系统升级为**多租户 SaaS**:一套代码服务 N 家图书馆。**平台/B 端 PM 能力代表项目**:抽象 + 隔离 + 配额计费 + API 生态。

## 角色与权限
| 角色 | 权限 |
|---|---|
| 平台管理员 platform_admin | 租户 CRUD、套餐管理、全平台数据、审计日志、API 全局视图 |
| 租户管理员 tenant_admin | 本租户:用户管理、图书管理、API Key、配额查看 |
| 租户成员 tenant_user | 本租户:检索、借阅自己的数据 |

## 功能模块
| 模块 | 说明 |
|---|---|
| 租户管理 | 创建/编辑/停用租户(名称/联系人/套餐/到期日);租户列表+用量 |
| 套餐管理 | 免费版(10用户/100本/API 1000次/月)、专业版(50用户/1000本/1万次)、企业版(不限/自定义): 配额字段可配 |
| 数据隔离 | 所有业务表带 tenant_id;查询强制 tenant_id 过滤(行级隔离);演示页展示 3 种隔离方案对比(库/表/行) |
| 用户体系 | 用户属于租户;平台管理员登录平台后台,租户管理员/成员登录各自租户(URL 带租户域名参数或登录时选择) |
| 业务(图书) | 简化版图书+借阅,全部按租户隔离(两个租户数据互不可见) |
| API 平台 | 每个租户自动生成 API Key;开放接口 /api/v1/books、/api/v1/borrows(需 X-API-Key);调用限流(每分钟 N 次);调用日志(时间/接口/状态/租户) |
| 配额与用量 | 租户用量(用户数/图书数/API 本月调用)对照套餐配额,超额标红+拦截(API 返回 429, 新建用户拦截) |
| 审计日志 | 平台级审计:谁在何时做了什么(登录/建租户/改配额/API 调用) |

## 隔离与计费设计(文档页必写)
- 三种隔离方案对比:独立库(最安全贵)/独立表(折中)/共享表+tenant_id(本系统采用,成本低,需严防漏过滤)
- 计费:按月订阅,超配额可升级;演示用配额数字即时生效

## 边界场景(必做)
1. 租户 A 的成员登录后看不到租户 B 的任何图书(硬隔离: 查询强制过滤+URL 参数校验)
2. 超出用户配额时,租户管理员创建用户被拦截
3. 超出 API 配额:返回 429 + 友好 JSON
4. 停用租户:成员无法登录,API 拒绝
5. 平台管理员可看全部租户用量,但不可改业务数据(只读越权控制)

## 关键指标
租户总数、本月新增租户、API 调用总量、配额超限数、各套餐分布
